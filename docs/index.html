Why Try It

Most coding agents can edit files. oneshot gives them a repeatable operating loop that is observable, resumable, and safe enough to run while you do something else.

01

Real isolation

Every task starts in a fresh git worktree from the target branch. Your checkout stays clean, and parallel runs do not collide.

02

Agent work you can inspect

Runs emit structured JSONL events, durable ledger entries, changed-file summaries, step timings, and recoverable failure state.

03

Workflow presets

Use ship, review, fix-ci, research, docs, or swarm-review instead of rewriting the same prompt every time.

04

Tool protocol ready

oneshot mcp serve exposes the same runtime to other agents as tools: run, status, policy, workflows, and eval summary.

The Pipeline

Eight steps. Each run gets its own git worktree, so your main branch stays clean.

1

Validate

git

Checks the repo exists and fetches latest from origin

2

Worktree

git

Creates an isolated /tmp worktree from origin/main

3

Route

Adaptive

Chooses provider, reasoning, context, verification, and fast/deep mode

4

Plan

Config

Reads the codebase, outputs an implementation plan

5

Execute

Config

Implements the plan following repo conventions

6

Draft PR

Config

Creates branch, commits, and writes PR metadata; runtime opens or updates the draft PR

7

Review

Config

Reviews the diff for bugs, types, and security. Fixes issues directly.

8

Finalize

git/gh

Pushes review fixes and marks the PR ready

Worktrees are cleaned up after every run. Parallel runs are safe.

Quick Start

1

Prerequisites

On your laptop

  • Bun
  • SSH access to your server

On your server

  • Bun
  • Codex CLI or Claude Code CLI
  • GitHub CLI (authenticated)
  • OPENAI_API_KEY for Codex mode or ANTHROPIC_API_KEY for Claude mode
2

Install

Install globally on both your laptop and server:

bun install -g oneshot-ship

Or from source:

git clone https://github.com/ADWilkinson/oneshot-cli.git
cd oneshot-cli && bun install && bun link
3

Configure

oneshot init

Sets up SSH host, workspace path, provider, API keys, and per-phase model preferences. Saves to ~/.oneshot/config.json.

Then run oneshot doctor to verify package freshness, local binaries, SSH reachability, remote binaries, and recent event streams.

Repos should live as <org>/<repo> under your workspace path. Repo slugs are strict owner/repo values; nested paths and .. are rejected before filesystem access.

~/projects/
  acme/api/
  acme/web/
4

Ship

oneshot acme/api "fix the login timeout bug"

That's it. oneshot handles the rest.

Usage

oneshot <repo> "<task>"                 # ship a task
oneshot <repo> <linear-url>              # ship from a Linear ticket
oneshot <repo> "<task>" --bg             # fire and forget
oneshot <repo> "<task>" --local          # run locally, no SSH
oneshot <repo> "<task>" --workflow ship  # apply a workflow preset
oneshot <repo> "<task>" --model gpt-5.5  # override configured plan/PR model
oneshot <repo> "<task>" --deep-review    # force exhaustive review
oneshot <repo> "<task>" --branch staging # target a different branch
oneshot <repo> "<task>" --worktree-root /tmp/agents
oneshot <repo> --dry-run                 # validate only
oneshot init                             # configure
oneshot stats                            # recent runs + timing
oneshot runs                             # durable run ledger
oneshot runs --json --limit 10           # list runs for automation
oneshot status <run-id|events-file> --json
oneshot eval --json                      # summarize outcomes
oneshot doctor                           # setup and remote health checks
oneshot doctor --repo acme/api           # setup + checkout health
oneshot route "fix failing CI" --json    # inspect hidden route
oneshot workflow list                    # inspect workflow presets
oneshot workflow show fix-ci --json      # inspect one workflow preset
oneshot policy init                      # create .oneshot/policy.json
oneshot policy init --path ./repo        # write policy elsewhere
oneshot mcp serve                        # expose MCP tools

Flags

Flag Short Description
--model -m Override the configured plan/PR model for this run
--branch -b Base branch (default: main)
--base-path Override the workspace path used to locate the repo
--worktree-root Override where temporary git worktrees are created
--workflow Apply a workflow preset such as ship, review, fix-ci, research, docs, or swarm-review
--deep-review Force exhaustive review mode (bypasses auto-classification)
--local Run locally instead of over SSH
--bg Run detached in background (returns PID + log path)
--dry-run -d Validate repo exists without running the pipeline
--events-file Mirror JSONL events to an additional file for machine consumption
--repo With doctor, verify a specific owner/repo checkout exists
--provider With route, choose the fallback provider (codex or claude)
--help -h Show help
--version -v Show version

Configuration

~/.oneshot/config.json, created by oneshot init. Only host is required for SSH. Local mode works without a config file.

{
  "host": "user@100.x.x.x",
  "basePath": "~/projects",
  "worktreeRoot": "/tmp",
  "provider": "codex",
  "routing": { "enabled": true },
  "linearApiKey": "lin_api_...",
  "claude": {
    "model": "opus",
    "timeoutMinutes": 180
  },
  "codex": {
    "model": "gpt-5.5",
    "reasoningEffort": "xhigh",
    "reviewModel": "gpt-5.5",
    "reviewReasoningEffort": "xhigh",
    "timeoutMinutes": 180
  },
  "phases": {
    "classify": { "model": "gpt-5.5", "reasoningEffort": "medium" },
    "plan": { "model": "gpt-5.5", "reasoningEffort": "xhigh" },
    "execute": {
      "model": "gpt-5.5",
      "reasoningEffort": "xhigh"
    },
    "review": {
      "model": "gpt-5.5",
      "reasoningEffort": "xhigh"
    },
    "deepReview": {
      "model": "gpt-5.5",
      "reasoningEffort": "xhigh"
    },
    "pr": { "model": "gpt-5.5", "reasoningEffort": "high" }
  },
  "stepTimeouts": {
    "planMinutes": 20,
    "executeMinutes": 60,
    "reviewMinutes": 20,
    "deepReviewMinutes": 20,
    "prMinutes": 20
  }
}

phases is optional. If omitted, every agent phase uses the selected provider and its default model settings. Stale per-phase provider values from older configs are ignored when adaptive routing is off. With routing.enabled, oneshot's adaptive router can silently choose Codex or Claude per task while preserving each provider's configured frontier model.

Options

Key Required Description
host SSH only SSH target (e.g. user@192.168.1.10)
basePath No Root directory containing your repos. Default: ~/projects
worktreeRoot No Scratch directory for temporary git worktrees. Default: /tmp
provider No Fallback agent provider when adaptive routing is off or no route rule wins. Default: codex
routing.enabled No Enables invisible provider and reasoning routing. Codex and Claude still use their configured frontier model
anthropicApiKey Claude only Falls back to ANTHROPIC_API_KEY env var
linearApiKey No Enables Linear ticket integration
claude.model Claude only Default Claude model. Default: opus
codex.model Codex only Default Codex model. Default: gpt-5.5
codex.reasoningEffort Codex only Default Codex reasoning effort. Default: xhigh
codex.reviewModel Codex only Default for review phases. Default: same as codex.model
codex.reviewReasoningEffort Codex only Default review reasoning effort. Default: same as codex.reasoningEffort
phases.<phase>.model No Exact model for that phase under the selected provider
phases.<phase>.reasoningEffort No Reasoning effort for that phase, e.g. medium, high, xhigh. Passed to Codex and to Claude via --effort
stepTimeouts No Per-step timeout overrides in minutes

Runtime Controls

Recent runs are mirrored into a durable ledger under ~/.oneshot/runs. Workflow presets, policy packs, eval summaries, and the MCP server make oneshot usable as an agent workflow engine instead of a one-off shell command.

Observe

Inspect recent work and read one run or event file as JSON.

oneshot runs oneshot status <run-id|events-file> --json

Shape

Pick a workflow preset or add repo policy.

oneshot workflow list oneshot policy init

Integrate

Expose the public runtime to any MCP-capable agent.

oneshot mcp serve oneshot eval --json 
oneshot runs
oneshot status <run-id|events-file> --json
oneshot eval --json
oneshot workflow list

oneshot policy init
oneshot mcp serve

Linear Integration

Pass a Linear URL instead of a task string. oneshot fetches the ticket and uses it as context.

oneshot acme/api https://linear.app/acme/issue/ENG-142
1

Fetches issue title, description, and comments via GraphQL

2

Formats ticket as context for the planning step

3

Uses the issue ID in the PR branch name (e.g. oneshot/eng-142-1712345678901)

4

After PR creation, moves the ticket to "In Review" and comments the PR URL

Requires linearApiKey in your config.

Customization

Repo Instructions

Put a CLAUDE.md or AGENTS.md in any repo root. oneshot passes repo instructions to the configured agents for planning and execution.

Coding standards, architecture decisions, test requirements, whatever.

Prompt Templates

Edit the prompt files to change pipeline behavior:

prompts/plan.txt How the plan agent explores and plans
prompts/execute.txt How the execute agent implements changes
prompts/review.txt How the review agent reviews the diff
prompts/pr.txt How the PR agent writes branch/commit/PR metadata

Templates use {{variable}} placeholders replaced at runtime.
