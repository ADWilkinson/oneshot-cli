# GAL-739: stop the planner from wedging, make step 4 observable

## Problem

Two recent `oneshot --local --bg` dispatches against `personal/galleonlabs-zkp2p` stalled inside step 4 ("Planning with Claude") for 96 min and 3h52m before the operator killed them by hand. The child `claude -p` process was alive and burning CPU, so the plan prompt was still executing — the pipeline had no way to surface progress and the step-timeout abort did not actually kill the runaway child.

Three independent bugs make this fail silently:

### Bug 1 — `killProcessTree` does not reach the LLM child

`src/exec.ts` `killProcessTree` only signals the top-level `bash -c` PID. The spawn call in that file does NOT set a new process group, so when `planMinutes` elapses the runtime sends `SIGTERM` to bash, bash dies, but the grandchild `claude -p` (and `codex` in other steps) is reparented to PID 1 and keeps running. That is exactly the state captured on dappnode: the oneshot parent had been killed, yet orphan `claude -p` processes with 2h+ elapsed time were still live at 8-13% CPU.

### Bug 2 — step 4 emits no intermediate log/event once it starts

`src/steps/plan.ts` shells out to the Claude CLI via the shared runner with `stream: true`, but the runner only streams the raw child stdout. `claude -p` on `opus` writes nothing until the plan is complete, so the operator sees `[4/8] Planning with Claude…` and then silence for the entire `planMinutes` (currently 60) window. There is no heartbeat, no "still working after Nm" log, no events.json entry, no way to tell "wedged" from "slow".

### Bug 3 — the 60 min `planMinutes` default was never tuned for deep mode on large repos

Deep-mode plans against monorepos with 3000+ line target files routinely run 40+ min. When they slip past 60, the timeout path fires but Bug 1 leaves the child running so nothing visibly happens — the operator still has to kill manually.

Scope: we only need to make these failures loud, bounded, and recoverable. Do NOT redesign the pipeline or add a heuristic to skip deep mode.

## File-by-file changes

Touch ONLY these files. Do not rename, refactor adjacent helpers, or introduce new abstractions.

### 1. `src/exec.ts` — actually kill the process tree

Change the spawn call inside the `exec` helper (the one that runs `bash -c <command>` via `Bun.spawn`) so the spawned bash and all its descendants live in their own process group, then signal the group in `killProcessTree`.

- In the spawn options, add `detached: true` so Bun sets the new session / pgid. Verify the Bun 1.x option name before committing — grep the Bun types under `node_modules/@types/bun` or `node_modules/bun-types` to confirm `detached` is the supported key. If Bun uses a different key, use the one that's actually supported.
- In `killProcessTree`, after `process.kill(proc.pid, …)` already signals the leader, ALSO signal the process group using the negated PID form: `process.kill(-proc.pid, 'SIGTERM')` first, then the follow-up `SIGKILL` after 5s ALSO via the negated PID. Wrap both in try/catch; ESRCH is expected once the group is empty. Keep the existing single-PID `process.kill(proc.pid, …)` calls inside the same try/catch so a failed group-signal still reaches the leader.
- If `detached: true` is not the correct Bun option, fall back to prefixing the bash invocation with `setsid` — i.e. the spawned argv becomes `['setsid', 'bash', '-c', command]` on Linux and plain `['bash','-c', command]` on darwin (macOS `setsid` is not always present — detect via `process.platform`). This is a last resort; prefer the Bun-native detached option.
- Document the reason with a single one-line `//` comment above the spawn call — nothing more.

Acceptance test: after the patch, a synthetic sleep-grandchild scenario must return within ~6s of the timeout AND leave no `sleep` visible via `pgrep -f 'sleep 30'` five seconds after the timeout fires. Add a `bun:test` case in `src/exec.test.ts` (NEW file, minimal — one describe, one test) that spawns a child-of-bash (the command is the string `bash -c "sleep 30"` passed into the helper, which itself wraps it in `bash -c …`, producing a bash → bash → sleep grandchild), triggers the timeout, waits 6s, then asserts via `Bun.spawn(['pgrep','-f','sleep 30'])` that the grandchild is gone. Skip the test via `test.skipIf(process.platform !== 'linux')` so CI stays portable.
